Security notes

kroger-mcp holds the tokens for your Kroger shopping account and can add to your cart, so it's worth knowing how it protects them.

Two auth layers

  • Who can use the server (Claude → kroger-mcp). Optional OAuth on the MCP endpoint, delegated to your own identity provider. kroger-mcp validates JWT access tokens (signature, issuer, audience, expiry and the at+jwt type) on every request.
  • Whose Kroger account it acts on (kroger-mcp → Kroger). Kroger's own OAuth. Store and product lookups use your developer app's token; the cart uses your shopping account, which you link once in a browser.

Running without auth

Don't expose the server without MCP auth beyond localhost or a network you trust. With auth off, anyone who can reach it can add to your cart, or link their own Kroger account in place of yours so your later adds land in their cart.

With auth off, the server refuses to listen beyond loopback unless you set KROGER_MCP_ALLOW_UNAUTHENTICATED=true. The sample compose file publishes the port on 127.0.0.1 only. If an account is already linked, kroger_login warns before replacing it, and the server logs the swap.

Linking safely

Kroger's redirect has to reach the server without a bearer token, so the callback route is open. It only accepts a single-use state from a login URL issued through an MCP call in the last 15 minutes, so nobody can link an account without first getting a login URL from the server.

What it stores

The linked account's access and refresh tokens, and your default store, live in state.json in the data directory (a Docker volume in the sample setup). Treat that file like a password. The server has no Kroger credentials of its own: you register your own developer app and agree to Kroger's developer terms.

Supply chain

Workflows pin every action to a commit SHA with minimal permissions, dependencies are scanned with govulncheck (and CodeQL once the repo is public), and release images ship an SBOM and build provenance alongside checksummed binaries.

Reporting a vulnerability

Please report privately through GitHub Security Advisories, as described in SECURITY.md, not in a public issue.
